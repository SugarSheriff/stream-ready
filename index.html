Stream Ready

A Blender add-on that gets a scene ready for Miris 3D streaming. It checks the scene against Miris's own error codes, exports OpenUSD with the settings Miris's guide asks for, inspects the exported files with OpenUSD, and publishes them through the Miris API, then watches until the asset is streamable.

03 — Found by the tests

The ×1562 that never reached the file

The guide calibrates HDRI lighting by setting an "Export Light Intensity" node to Blender intensity × 1562. The headless Blender test exported that setup and read the result back with OpenUSD. With the export node set but not the one wired into the Background, Blender 4.2 wrote DomeLight color = (1, 1, 1). Nothing errors. The calibration just silently never makes it into the file.

So the add-on stopped relying on node wiring. It reads the intensity, exports, then sets the DomeLight color itself. tests/blender_smoke.py asserts the value in the actual exported USD.

04 — What's in the repo

The real building blocks

Python · bpy

The add-on

Sidebar panel, one-click fixes, and Export Only for people without an API key. Uploads run on a worker thread, so Blender never freezes, and Cancel marks the upload canceled on Miris.

 Python · OpenUSD

Folder check

Opens the exported stage with pxr, which ships inside Blender. It resolves every dependency, evaluates visibility and purpose, and measures world bounds × metersPerUnit against Miris's 1 cm³–100 km³ limit.

 Python · stdlib

SigV4 + multipart

Miris issues temporary storage credentials, so the client signs its own uploads. No boto3. Tested byte for byte against AWS's published S3 examples, and an interrupted multipart upload is aborted.

 Python · REST

Miris client

Built from Miris's OpenAPI spec: reserve, upload status with a size manifest, job polling, and asset-scoped viewer keys. Errors are parsed as problem+json, and the API key is never sent to the storage host.

 Python · http.server

Mock Miris

A local API and S3 storage that recompute every signature, enforce the manifest, and run the same checks as "processing", reporting Miris's error keys. It injects 503s and 429s on request.

 Docs

Verified vs. assumed

The README separates what's confirmed (spec, test vectors, real Blender exports) from the guesses the public docs leave open, so a first live run knows exactly what to check.
